# R001 计划：学习率衰减 + 加强自对弈搜索

## 这一轮要回答的问题

v4 对固定锚点仍在进步，但最近对自己的旧版本只有 0.52–0.54，学习率一直是恒定的 2e-4。用户要求两项改动同时生效：
(1) 学习率衰减，并修好"续训时学习率不跟随配置"的问题；(2) 提高自对弈中全量搜索的比例和模拟次数。
本轮回答：这两项能否让训练越过平台，并给出对规则机器人（"一般玩家"代理）的第一组强度数字。

## 发现并修复的问题（学习率）

- 原实现是 `LambdaLR`（只有预热、之后恒定），它的状态和优化器的 param_groups（含 lr、weight_decay、betas）都存进
  checkpoint、续训时原样恢复：**改 config 里的学习率对续训的实验不起作用**。
- 修复：学习率是本实验训练步数的纯函数 `lr_factor(step, warmup, lr_schedule)`，每一步训练前写入优化器；续训时 Adam 的矩估计保留，
  lr / weight_decay / betas 按 config 重写（日志里打印旧值与新值）。日志与 metrics.jsonl 记录实际用于最后一步的 lr。
- 测试：`LearningRateTest`（每一步的 lr 等于计划值；续训改配置后 lr、weight_decay、betas 都按新配置）。

## 改动（对照 v4）

| 参数 | v4 | R001 | 对应要看的指标 |
|---|---|---|---|
| 学习率 | 预热 200 步后恒定 2e-4 | 预热 100 步到 2e-4，分段线性：第 4000 步 5e-5，第 10000 步 2e-5 | metrics 的 lr；held-out policy CE / value CE 随 lr 下降是否继续降 |
| mcts_full_search_prob | 0.06 | 0.15 | 每局全量搜索数（约 7.5 → 19） |
| num_mcts_simulation_per_step（全量） | 128 | 256 | 策略目标熵 target_entropy、held-out policy CE |
| mcts_fast_num_simulation（快速） | 16 | 24 | 对局质量（平均回合数、截断率） |
| num_samples_per_game | 5 | 12 | 全量搜索占算力约 65%，只取 5 个会浪费一半以上 |
| train_sample_reuse | 1.2 | 1.5 | 每 iteration 训练步数 ≈ 1024 × 11 × 1.5 / 256 ≈ 65 |
| transition_buffer_len | 100000 | 150000 | 约 12 个 iteration |
| 起点 | v3b 权重 | v4 latest.pth 的权重，新优化器；回放池先装 v4 最新 15 万条 | — |
| 基准 | 无 | 每次评估附带 96 局 vs 3×lookahead、96 局 vs 3×heuristic | bench win_share |

每步平均模拟次数 0.06×128 + 0.94×16 ≈ 23 → 0.15×256 + 0.85×24 ≈ 59（约 2.6 倍），预计约 6–7 局/秒、每个 iteration 约 2.5–3 分钟，
9 小时约 180–200 个 iteration、约 1.2 万训练步（学习率计划按这个长度设计）。

## 判定

- **supported**：训练中基准 vs 3×lookahead 的最后 3 次均值比第 1 次高 ≥ 0.05，且独立基准中本轮最好检查点对 v4 起点 ≥ 0.55。
- **refuted**：两项都没有达到，且 held-out 指标没有改善（学习率降下来后 policy CE / value CE 不降）。
- **inconclusive**：其余情况（例如对起点有提升但基准没动，或反之）。

起点测量：启动前用 `benchmark_splendor.py` 测 v4 latest 对 lookahead / heuristic（存 benchmark_start.json）。

## 风险

- 吞吐降到约 2/5：每小时的对局数少，但每个样本的目标更好；训练步数 / 小时与 v4 相近（65 步 × 约 20 iteration/小时）。
- 回放池开头是 v4 的样本（较弱的搜索产生）：约 12 个 iteration 后全部换成新样本。
- 新优化器：Adam 矩估计从零开始，用 100 步预热。
