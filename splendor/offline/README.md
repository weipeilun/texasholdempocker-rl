# 璀璨宝石线下对局（摄像头 + 视觉模型 + 机器人座位）

在实体牌桌上和训练出的模型对局。原来的网页模拟器 `splendor/server.py` 不受影响。

- 牌桌正上方放一个摄像头，每隔几秒把画面发给视觉大模型，读出整个牌局。
- 规则引擎当裁判：
  - 推断人类玩家做了什么；
  - 校验每一次状态变化；
  - 记下牌堆翻出的新牌。
- 机器人座位由模型（或规则机器人）决定动作，在大屏幕上给出指令，由人类代理在桌上执行。
- 摄像头确认代理执行完毕、桌面与预期一致后，自动进入下一位玩家。

## 启动

```bash
python -m splendor.offline --host 127.0.0.1 --port 8766          # 在 GPU 服务器上（机器人模型用 GPU）
ssh -L 8766:localhost:8766 infimory-gpu                           # 在自己的电脑上
# 浏览器打开 http://localhost:8766
```

- **第一次打开**：在登录页创建的第一个账号是管理员。之后默认不能自助注册；需要更多账号时用 `--allow-register` 启动。
- **数据目录**：`~/.splendor_offline`，权限 0700。里面有：
  - 账号：PBKDF2 加盐哈希；
  - 各账号的视觉模型设置，含 API Key，只保存在服务器上，页面只显示掩码；
  - 每局的完整记录 `games/game-*.json`。
- **浏览器摄像头**：浏览器只在安全上下文里允许打开摄像头，有两种办法：
  - 用 `localhost` 打开（上面的 ssh 隧道就是）；
  - 用 HTTPS 启动，局域网里的其他设备（手机、平板）也能当摄像头：
    ```bash
    openssl req -x509 -newkey rsa:2048 -nodes -days 365 -subj "/CN=splendor" \
        -keyout ~/.splendor_offline/key.pem -out ~/.splendor_offline/cert.pem
    python -m splendor.offline --host 0.0.0.0 --certfile ~/.splendor_offline/cert.pem --keyfile ~/.splendor_offline/key.pem
    ```
- **服务器本机摄像头**：`--camera 0`（USB 设备号）或 `--camera rtsp://…`（网络摄像头）。由服务器直接取帧，不需要浏览器页面。
- **机器人**：
  - 默认用 `models/splendor_final/` 的最终模型，部署搜索为 512 次模拟、considered 8、对手走先验；
  - `--sims`、`--weights`、`--device` 可改；
  - 模型在机器人第一次行动时加载，GPU 上每步约 3–5 秒。

## 页面

| 页面 | 用途 |
|---|---|
| `/` 控制台 | 牌局状态、提示、告警、对局记录（玩家动作 / 牌堆翻牌 / 贵族 / 机器人指令）、摄像头预览与识别状态、手动操作 |
| `/screen` 大屏幕 | 机器人的指令，大字号，给人类代理看；轮到人类时显示提示；有错误时显示红色告警 |
| `/camera` 摄像头 | 在接摄像头的电脑或手机上打开，把画面定时上传到服务器 |
| `/settings` 视觉模型设置 | API 地址（OpenAI 或中转）、API Key、模型（可从接口读取列表）、识别间隔、桌面布局说明、试识别 |

## 一局的流程

1. 在“设置”里填 API 地址、Key、模型，用“试识别当前画面”确认能读出牌局。
2. 打开“摄像头”页面开始推流；在“大屏幕”页面放到大屏上。
3. 控制台“新建对局”：四个座位按行动顺序，每个座位选人类或机器人；机器人可选训练模型或规则机器人。
4. 摆好开局：12 张牌、5 位贵族、银行筹码。识别结果会预填到“确认开局”，可逐张修改，确认后开始。
5. 对局中：
   - **人类回合**：玩家直接在桌上操作。连续两次识别结果一致、且能用该玩家的一个合法回合解释时，自动记入。
     - 回合包括：动作、翻出补位的新牌、退回多余筹码、选择贵族。
     - 做到一半也能识别，例如已拿筹码还没退回、已买牌还没补位。控制台和大屏幕会提示下一步。
   - **机器人回合**：控制台和大屏幕显示指令。代理照做后，桌面与指令一致即记入。
     - 指令包括：拿哪些筹码、买 / 预留哪张牌、如何支付、退回什么、补牌。
     - 需要翻牌补位时，新牌由摄像头读出。
6. 识别不可靠时可以手动操作：
   - 录入当前玩家的合法动作；
   - 录入翻出的牌；
   - 确认机器人指令已执行。像“拿三枚又退回同样三枚”这种桌面看不出变化的指令，必须手动确认。
   - 在多种合法解释里选一种；
   - 撤销上一步。撤销后实体桌面也要恢复到上一步的局面。

## 告警

| 告警 | 含义 |
|---|---|
| 摄像头画面不完整 | 视觉模型报告有区域被遮挡、出画或看不清 |
| 摄像头画面已 N 秒没有更新 / 还没有画面 | 推流断了 |
| 识别出的牌局不符合游戏规则 | 单次识别本身就违规：筹码总数不对、同一张牌出现两次、预留超过 3 张、非当前玩家持有超过 10 枚等。多半是识别错误或摆放有误；这次识别不会被采用 |
| 桌面变化无法用当前玩家的合法动作解释 | 连续三次识别都一样，但不是合法回合，例如一次拿 4 枚、银行不足 4 枚时拿两枚同色、从牌堆暗扣、非当前玩家动了自己的东西。告警会列出与预期局面的逐项差异 |
| 代理执行的动作与指令不符 | 桌面变成了另一个合法动作的结果 |
| 有多种合法解释 | 请在控制台选择实际发生的动作 |
| 调用视觉模型失败 / 没有配置 API Key | 接口错误、超时、输出不是 JSON |

## 规则（与训练时一致）

- 四人局，银行五色各 7 枚、黄金 5 枚。
- **只能预留桌面上公开的牌**，不能从牌堆暗扣。预留牌正面朝上放在自己面前，所有人可见。
- 回合结束时最多 10 枚筹码，多出的逐枚退回（任意颜色，含黄金）。
- 满足贵族条件时：只满足一位则自动获得，满足多位则自选一位。
- **有人到 15 分立即结束，不补完本轮**。分高者胜；同分时已购发展卡少者胜。
- 没有合法动作时被迫跳过；四人连续跳过判平局。

## 视觉识别的建议

- 摄像头垂直向下，桌子占满画面，光线均匀。
- 筹码按颜色分开、不要叠得太高；已购发展卡按颜色错开叠放，能数出张数。
- 动作做完后手离开画面。
- 设置里的“桌面布局”描述要和实际座位一致。
- “附带上一次确认的局面”默认打开：给模型一个对照，但以照片为准。
- **费用**：每次识别是一次带图片的调用。间隔 5 秒时每小时约 720 次；画面没有更新时不会调用。

## 代码

| 文件 | 内容 |
|---|---|
| `table.py` | 可观察的牌桌状态 TableState；视觉 JSON → 状态（牌按等级、颜色、分数、花费对应到牌库）；单次识别的规则检查；用合法回合解释一次变化（`explain`） |
| `session.py` | 一局：识别结果的稳定性、人类回合推断、机器人指令与执行确认、提示、告警、记录、撤销、手动操作 |
| `robots.py` | 训练模型（`models/splendor_final/play_agent.Agent`）与规则机器人 |
| `vision.py` | OpenAI 兼容的 Chat Completions 调用（图片输入、JSON 输出；对不支持 temperature / response_format 的模型自动去掉重试）、提示词、模型列表 |
| `accounts.py` | 账号、登录会话、各账号的设置 |
| `server.py` | 标准库 HTTP 服务、视觉识别循环、本机摄像头 |
| `simulate.py` | 测试用的“完美摄像头” |

测试：

```bash
python -m unittest splendor.tests.test_offline         # 模拟牌桌 + 完美摄像头：整局人类 / 机器人 / 半完成的回合、非法动作、识别违规、代理执行错误、撤销
python -m unittest splendor.tests.test_offline_http    # HTTP 端到端：登录、设置、假的 OpenAI 兼容接口、开局、多个回合、告警（约 1 分钟）
```

一个服务进程只管一张牌桌、一局对局。
